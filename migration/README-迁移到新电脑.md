# 迁移到另一台电脑（配合 WorkBuddy 使用）

> 适用：把这套「润致公众号自动发布工具」从当前电脑搬到新电脑上继续用。
> 全程约 15-30 分钟。扫码发表需要新电脑装 WorkBuddy + Node.js；只做 API 自动发布只需 Python。

---

## 一、先搞清楚要带走什么

| 内容 | 说明 | 是否必须 |
|---|---|---|
| `app/` 程序代码 + 页面 | 主程序（app.py 等 + static 页面） | ✅ 必须 |
| `app/.env` | 密钥配置（DeepSeek Key、微信 AppSecret、企业微信通知 Webhook） | ✅ 必须 |
| `app/data/poster.db` | 历史任务/主题/产品/账号设置 | ✅ 建议（不带就是全新空库） |
| `app/data/articles/` | 历史生成的文章正文 | ✅ 建议 |
| `wechat/covers/` | 扫码发布用的本地封面图 | ✅ 扫码需要 |
| `docker/` | Dockerfile / compose / requirements.txt | ✅ 必须（requirements 装依赖用） |
| 微信登录态 `~/.workbuddy/wx-profile` | 扫码发表免登录用 | ⚠️ 可选，跨机器可能失效 |
| `~/.workbuddy/binaries/...`（Python/Node） | 运行环境 | ❌ 新电脑自己装 |

**打包脚本已自动处理**：会自动排除二维码图片、日志、缓存、探针脚本等无用文件。

---

## 二、第 1 步：在当前电脑打包

在项目根目录执行（`migration` 目录已准备好脚本）：

```bash
python migration/make_package.py
```

产物：`migration/poster-migration.zip`（约几 MB）

如果也想要微信登录态（**不保证在新电脑有效**，但可以省一次登录）：

```bash
python migration/make_package.py --with-profile
```

产物：额外的 `migration/wx-profile.zip`（约 100-200MB）

把 zip 拷到新电脑（U 盘 / 局域网 / 微信文件传输均可）。

> ⚠️ 包里含密钥（.env），传输时注意不要发到公开群。

---

## 三、第 2 步：新电脑准备环境

| 需要 | 用途 | 获取方式 |
|---|---|---|
| **WorkBuddy** | 后续用 AI 维护这套程序（打开这个项目目录即可） | 官网下载安装 |
| **Python 3.9+** | 运行主程序 | python.org，安装时勾选 “Add to PATH” |
| **Node.js 18+** | 只有「扫码发表」才需要 | nodejs.org（LTS 版） |
| **Chrome 或 Edge** | 只有「扫码发表」才需要 | 装 Chrome 最省事 |

> 提示：WorkBuddy 自带托管的 Python/Node，install.py 会优先使用；但没有 WorkBuddy 时用系统安装的版本也行。

---

## 四、第 3 步：解压并安装

1. 把 `poster-migration.zip` 解压到任意目录（**建议路径不含空格**，例如 `D:\poster`）。
2. 如果带了登录态，把 `wx-profile.zip` 放到**同一目录**（install.py 会自动还原）。
3. 在该目录打开命令行（PowerShell），执行：

```bash
python install.py
```

脚本会自动完成：
- 创建虚拟环境 `.venv` 并安装 Python 依赖（走清华镜像，较快）
- 安装 `playwright-core`（扫码发表用）
- 检测浏览器
- 还原微信登录态（若提供了 zip）
- 生成一键启动脚本 `start.bat` / `start.sh`

---

## 五、第 4 步：启动并验证

双击 `start.bat`，看到类似输出即成功：

```
🚀 润致公众号自动发布工具 已启动 → http://127.0.0.1:8765
```

浏览器打开 `http://127.0.0.1:8765`，检查：
1. 页面能打开、主题库有 20 个主题
2. 「公众号」「产品库」里的数据在（若带了 poster.db）
3. 点一下「🔔 发送测试通知」，企业微信群能收到 → 说明密钥与网络都通了

**扫码发表首次使用**：点扫码发布时脚本会启动浏览器，如果登录态失效，浏览器会停在登录页 —— 手动扫码登录一次微信公众平台即可，之后登录态会保存在新电脑上。

## 六、⚠️ 两台电脑同时用同一个公众号（重要）

这是最容易出问题的场景，必须了解：

| 风险 | 后果 | 应对 |
|---|---|---|
| **重复发文** | 两台都开「每日定时」→ 同一批主题发两遍 | **只在一台开启「每日定时」**；程序已做跨设备防重兜底（发布前查微信端今日已发篇数，发现别的设备发过就跳过） |
| **微信登录态互踢** | 扫码发表依赖网页登录，同账号多端登录会互相挤下线 | 扫码发表**固定用其中一台**；哪台要用就先在那台重新登录 |
| **access_token 互相顶** | 同一账号 token 全局唯一，两边刷新会短暂互相失效 | 程序有自动重试，影响很小，无需处理 |

**推荐做法**：
- **A 机（主力）**：开启每日定时，负责自动发布
- **B 机（备用/演示）**：**关闭每日定时**，只在需要时手动发布

关闭方式：页面「⏰ 每日定时自动发布」开关关闭即可（设置会持久保存）。

## 七、常见问题

**Q：日志里提示找不到浏览器？**
设置环境变量 `CHROME_EXE` 指向浏览器，例如：
```
setx CHROME_EXE "C:\Program Files\Google\Chrome\Application\chrome.exe"
```
或把 Chrome 装到默认路径（脚本会自动探测）。

**Q：扫码时一直停在登录页？**
登录态失效了，手动扫码登录一次即可。若浏览器打不开，检查 Node 与 Chrome 是否装好。

**Q：想换个端口？**
编辑 `start.bat`，把 `--port 8765` 改成别的端口。

**Q：想让局域网其他设备访问？**
把 `start.bat` 里的 `--host 127.0.0.1` 改成 `--host 0.0.0.0`，其他设备访问 `http://<本机IP>:8765`。
（注意：本机防火墙需放行该端口）

**Q：数据想重新开始（清空历史）？**
删除 `app/data/poster.db` 即可，重启后会重建并自动种入 20 个默认主题。

**Q：能不能不用原生环境，直接 Docker？**
可以，但 **Docker 里没有浏览器，扫码发表不可用**；API 自动发布 + 每日定时完全可用。
方式见 `docker/README-NAS.md`。
